# X（旧Twitter）巡回 → ハツコレ取り込み 手順書

X本体は自動スクレイプが困難なため、**Claude for Chrome（ログイン済み実Chrome）で相場発信アカウントを巡回**し、
転売妙味のある商品／実売相場を構造化してこの受け皿JSONに落とし、`npm run ingest:x` でDBへ入れる。

## 役割（2026-08-01 決定）

X は**両方**に使う:
1. **新規商品ソース** … ミラーが拾えない「これから出る×抽選/数量限定」の入手困難品をハツコレに追加（`kind:"new"`）
2. **相場シグナル層** … 既存アイテムに X 上の**実売相場（メルカリ○万 等）**を付与（`kind:"resale"`）。駿河屋中古相場では取れないコラボ限定品の転売価格を補う

## 巡回の型（Claude for Chrome）

1. `src/data/xWatchlist.ts` の順にアカウントを開く（`tier:"price"` の実売相場系 → `tier:"alert"` の抽選/再販速報）
2. 各ポストから拾う判断軸:
   - **転売妙味**: 定価に対し実売が明確に高い／抽選・数量限定で入手困難／急上昇
   - **新規性**: ハツコレ未掲載か（既存なら `kind:"resale"` で相場だけ足す）
3. `kind:"new"` は一次情報（公式/商品ページ）URLを `url` に。無ければ出典Xポストを `url` か `resaleUrl` に
4. 拾った件を `x_watch_inbox.json`（このフォルダ）に追記
5. `npm run ingest:x -- --dry` で中身を確認（新規/相場付与/取りこぼし）→ 問題なければ `--dry` を外して本実行
6. 本番反映は他ソースと同じ（`ingest:x` は直接 Turso に書くので再デプロイ不要。ローカルdev.dbなら `.env` の Turso 変数なしで実行）

## 受け皿JSON（x_watch_inbox.json）

`x_watch_inbox.example.json` を複製して使う。gitignore 済み（機微な巡回メモを含むため）。

| フィールド | kind | 意味 |
|---|---|---|
| `kind` | 両方 | `"new"`（新規商品） / `"resale"`（既存へ相場付与） |
| `title` | new | 商品名 |
| `genre` | new(任意) | 省略時は自動分類（フィギュア/トレカ/…） |
| `eventType` | new(任意) | 予約/抽選/発売/開催/再販。省略時は本文推定 |
| `eventDate` / `eventDateText` | new(任意) | ISO日付 / 表示用テキスト |
| `price` | new(任意) | 定価 |
| `url` | new | 一次情報URL（無ければ出典Xポスト） |
| `imageUrl` | new(任意) | 画像 |
| `lottery` | new(任意) | 抽選/ランダム性あり→抽選タブで拾う |
| `itemId` | resale | 対象既存アイテムID（明示・最優先） |
| `match` | resale | 対象商品名（itemId無ければ曖昧一致、しきい値0.5） |
| `resaleYen` | 両方(任意) | 実売相場（円・整数） |
| `resaleText` | 両方(任意) | 相場ラベル素（例: "メルカリ 毎回20万前後"） |
| `resaleUrl` | 両方(任意) | 相場の出典（Xポスト/メルカリ検索URL） |
| `note` | 両方(任意) | 由来メモ（@ハンドル等・運用ログ用） |

## ソース被りの防止（2026-08-01）

Xから拾った商品がスクレイピング既存ソース（一番くじ倶楽部・snkrdunk 等）と被ると、一覧に同じ商品が2枚出てしまう。二重の防御で防ぐ:

1. **取り込み時（発生源で防ぐ）**: `kind:"new"` でも、まず **x_watch 以外の既存商品に曖昧一致**を試み、当たれば新規カードを作らず**その既存商品に相場だけ付与**（ログに `= [統合]`）。→ ソース被りのカードがそもそも生まれない。
2. **表示時（保険）**: スクレイパーが**後から**同じ商品を載せた場合に備え、`dedupeCrossSource`（`src/lib/itemFilter.ts`）が重複を畳む際に、落とす側の**相場/抽選情報を残す代表へ引き継ぐ**（`inheritEnrichment`）。→ X由来の実売相場が重複解消で消えない。

## マッチング（型番・作品ベース＝`scoreMatch`）

素の2-gram類似度だけだと、Xの略称や告知文ノイズで同一商品を取りこぼす一方、同一作品の別商品を共通接頭辞で誤結合しうる。`src/lib/xWatch.ts` の `scoreMatch` で両方に対処:
- **型番**（GD05等）が両方にあり **一致→同一商品(強)／食い違い→別商品(弱)**（GD05≠GD04を誤結合しない）。
- 型番が無く**作品が一致**する場合は、作品名・パック語を除いた**識別部(残差)の類似度**で判定（同一作品の別くじ/別弾を接頭辞の見かけスコアで誤結合しない）。
- 候補DBの引き方も、先頭数文字でなく**特徴トークン(型番＋作品名＋最長語)のOR**で引くので取りこぼしにくい。

## 自己点検（`npm run x:audit`）

`scripts/x_watch/audit.ts`。①巡回リスト整合性（重複ハンドル・不正enum・クラスタ分布）②x_watchカバレッジ（件数・ジャンル別・相場付与数）③**ソース被りの取りこぼし検出**＝x_watch商品に他ソースの強い相棒(scoreMatch≥0.6)がいれば報告。`--fix` で相場を既存側へ移し x_watch の重複を削除。

## 注意

- **Xの相場は発売済み商品に多いが、一覧は今後分＋日付未定しか出さない**ため、発売済みに付けた相場は詳細ページでしか見えない（＝別途「プレ値ビュー」等が要るかは要検討）。
- `kind:"resale"` は既存アイテムに**高額相場を貼る**ので、曖昧一致は高しきい値(0.5)。外れたら取りこぼしとして報告され、DBは汚れない。確実に紐づけたい時は `itemId` を使う。
- 相場は `marketSource="x"` で保存され、カードに「相場 メルカリ ¥…」と出る（駿河屋中古相場 `surugaya` と区別）。
